# 02 — Design Tokens & Themes

Use semantic CSS variables/tokens. Components must never depend on hard-coded palette values when a semantic token exists.

## Initial palette
Reference values to tune visually:
- TROC Red: #FF2D3D
- Near Black / Charcoal: #0E0E0E
- Dark Surface: #171717
- Grey: #2A2A2A
- Mid Grey: #7A7A7A
- Warm Off White: #F4F4F4
- White: #FFFFFF

Create semantic tokens such as:
- background
- surface
- surface-elevated
- surface-hover
- border
- border-strong
- text-primary
- text-secondary
- text-muted
- accent
- accent-hover
- accent-pressed
- focus
- positive
- warning
- destructive

Red is the brand accent, not the background of every component.

## Themes
1. Canada Dark — default
2. Canada Light

Architecture must allow more themes later without rewriting components. Theme selection should ultimately be user-configurable.

## Spacing
Use a consistent 4px/8px-derived scale with generous whitespace. Avoid compressed dashboard density unless a data table requires it.

## Radius
Modern but controlled. Small/medium radii for fields/cards; avoid excessively pill-shaped everything.

## Shadows
Very subtle. Dark theme should rely more on borders/surface separation than glowing shadows.

## Motion
Fast and purposeful, typically 120–220ms. Respect `prefers-reduced-motion`.
